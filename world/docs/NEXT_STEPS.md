# Expansion plan

The first release establishes a usable engine and a sourced seed collection. Expand it in reviewed slices rather than treating pin count as completeness.

## 1. A wider chronology

Add explicit, source-backed regional period packs. Priorities include China beyond selected heritage sites; South Asian states and social history; Southeast Asian maritime networks; West and Central African societies; the Americas beyond monumental centres; and twentieth-century decolonisation. Each pack should include places, processes, people and daily life, with living-community perspectives where available.

## 2. Historical area layers

Introduce a geometry model separate from narrative records. Every area needs its own source, snapshot date, meaning (administration, claimed control, cultural distribution, language or network), precision, license and review record. Never stretch one snapshot across centuries or infer a polity's territory from its capital point. Retain simultaneous and overlapping areas. Sparse or disputed evidence must remain visible to the reader.

The inspected historical-basemaps examples are quarantined by omission, not repaired wholesale. See `history-geodata-review.md`. Candidate data can be reviewed snapshot by snapshot without changing the current point-story layer.

## 3. Explicit connections

Add dated relations between records: trade, translation, migration, diffusion, conflict, dependency. Each connection needs evidence and relation type. The current journeys are reading sequences; they must not be relabelled as historical routes without that evidence.

## 4. Learner pathways

Add short guided questions, age-adjusted explanations and recall activities that stay attached to sources. Keep a general atlas as the common core, with family and classroom pathways layered on top. Do not turn approximate archaeological dating into precise quiz answers.

## 5. Independent repository

The application is self-contained under its own root, with no dependency on the China atlas. Copy that root into a dedicated repository when creation access is available. The GitHub delivery branch uses a `world/` subdirectory to avoid replacing the original app. No GitHub Actions workflow is required to run or check this release.
